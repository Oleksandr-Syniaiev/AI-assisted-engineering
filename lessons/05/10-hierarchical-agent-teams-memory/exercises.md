# Авторская демонстрация — Р5.10

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

Для уведомлений Workbench координатор выделяет API, implementation и verification. Все получают contract revision 3. Исполнитель B обнаруживает новый edge case и пишет finding, а не молча меняет общий контракт.

```json
{
  "kind": "finding",
  "based_on_contract": 3,
  "subject": "duplicate close notification",
  "status": "needs-owner-decision",
  "evidence": "<source-reference>"
}
```

Owner принимает решение и выпускает revision 4. Задачи, зависящие от revision 3, отмечаются для review. Если два агента одновременно записывают «окончательный» status в один файл, last-writer-wins может потерять решение; именно поэтому общий folder не заменяет протокол. Формат выше учебный, память и agents не запускались.

## Критерии разбора

Определить роли, task contracts и правила обновления/чтения общей памяти для иерархической команды. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
