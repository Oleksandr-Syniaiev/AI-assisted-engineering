# Авторская демонстрация — Р5.11

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

Для Workbench возьмём review одной spec. Агент domain проверяет states, security — actors, persistence — audit consistency. В фиксированном pipeline все три выполняются по очереди; в swarm участник передаёт задачу по найденной проблеме.

Негативный случай: domain отправляет security, security возвращает domain, оба ждут уточнения. Runtime останавливает процесс по лимиту, сохраняет unresolved question и передаёт owner. Без termination условие не разрешается от числа дополнительных сообщений.

```text
accept: findings связаны с criteria и проверены reviewer
stop: лимит ходов/стоимости либо повторяющийся unresolved handoff
compare: outcome, лишние передачи, latency, usage, review/rework
```

Никакого swarm trial не было. Исследования координации служат примерами методики измерения, а их topology rankings не переносятся на Workbench.

## Критерии разбора

Сравнить swarm-подход с централизованным и последовательным orchestration на ограниченной задаче и baseline. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
