# Авторская демонстрация — Р5.12

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

Агент Workbench подготовил deploy изменение closing API. Reviewer получает diff commit H, результаты checks на H, target staging и возможную migration. После подтверждения появляется H2 с другим SQL. Старое approval не переносится автоматически: одобренное действие изменилось.

```text
approval record:
subject: action digest / commit H
target: staging
decision: pending
owner: назначенная identity
expiry: по policy
timeout: действие не исполнять, сохранить state
```

При отказе run возвращает причину и не вызывает write tool. При долгом ожидании state хранится безопасно: serialized context может содержать чувствительные сведения. Схема учебная; approvals и запись в среду не выполнялись. Ожидается контролируемый переход, а не формальная печать «человек в цикле».

## Критерии разбора

Спроектировать владельца решения, approval points, эскалацию и безопасную остановку агентного процесса. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
