# Авторская демонстрация — Р5.09

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

В Workbench ветка A переименовывает `status` в API response, ветка B добавляет notification consumer, читающий старое поле. Разные файлы сливаются без текстового конфликта, но уведомления ломаются. Consumer contract test на объединённом дереве должен проявить несовместимость.

Другой случай: оба автора меняют одно условие transition. Git показывает textual conflict, но выбрать строку недостаточно. Owner сопоставляет обе причины с согласованными CLOSE criteria, затем фиксирует решение и запускает проверки на результате.

```text
merge evidence:
- точный кандидат/итоговый commit;
- разрешённый конфликт и rationale;
- проверки API/consumer и regression;
- оставшиеся неизвестные и решение owner.
```

Это проектируемый разбор. Repository protection, queue и tests здесь не настраивались. Зелёные независимые ветки не представлены как гарантия зелёной интеграции.

## Критерии разбора

Задать порядок интеграции параллельных изменений, разрешить конфликт и перепроверить объединённое состояние. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
