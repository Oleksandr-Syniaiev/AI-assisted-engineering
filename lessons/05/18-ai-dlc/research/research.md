- Статус: Research / Outline; готовый урок не написан.

## Исследовательские вопросы и ответы

### 1. AI-DLC — общепринятый стандарт?

Проверенные материалы подтверждают конкретный проект/workflow, а не универсальный стандарт определения и обязательного lifecycle. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 2. Что означает adaptive lifecycle?

Детализация и порядок артефактов могут зависеть от сложности/риска; exact criteria надо брать из выбранной версии. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 3. Чем workflow отличается от методологии?

Workflow — исполняемый набор шагов/правил конкретной реализации; методология шире и может существовать независимо от tooling. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 4. Какие артефакты сравнить?

Intent/requirements, design, task breakdown, code diff, test evidence, approvals и change history. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 5. Почему нужна версия?

Prompt/workflow изменения могут менять поведение; pinned commit позволяет связать разбор с известной реализацией. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 6. Как проверять совместимость с harness?

По docs и automated tests выбранной версии, затем пробным isolated run; текущий пакет не заявляет этот запуск. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

### 7. Какие требования production readiness?

Безопасные permissions, независимые checks, review ownership, observability, bounded execution, incident recovery и стоимость. [SRC-536](sources.md#src-536); [SRC-534](sources.md#src-534); [SRC-530](sources.md#src-530)

## Определение и границы

AI-DLC (AI-Driven Development Life Cycle) в данном curriculum — подход/реализация; первоисточник имени неоднозначен. Текущий публичный кандидат — aws-labs/aidlc-workflows, описывающий adaptive workflow steering rules для coding agents. Не считать это единственным определением AI-DLC.

## Механизм и архитектура

Репозиторий позиционирует общее ядро и несколько интеграции со средами выполнения. Для учебного анализа разобрать артефакты процесса, steering rules, адаптацию стадий, решения людей, путь тестирования и проверки и версионные различия; конкретный workflow требует чтения зафиксированную версию документации или кода перед написанием урока.

## Сравнение альтернатив

Матрица — качественная инженерная оценка, не benchmark. Перед выбором согласовать вес критериев с риском и измерять один и тот же outcome.

| Подход | Применимость | Освоение / внедрение | Сопровождение | Безопасность | Проверяемость | Стоимость |
|---|---|---|---|---|---|---|
| Обычный agile/ticket workflow | Зрелые небольшие команды с установленными review/test practice. | Низкое внедрение; гибко поддерживается командой. | Пересматривать при изменении процесса/границ; закрепить владельца и версию. | Знакомая модель, но агентные actions надо отдельно ограничить. | Сопоставить с независимым oracle и точным состоянием. | Небольшой overhead, высокая зависимость от индивидуальной дисциплины. |
| Generic SDD | Сложные/рискованные изменения с нуждой в traceable spec/tasks. | Средняя церемония; можно выбирать лёгкий/полный process. | Пересматривать при изменении процесса/границ; закрепить владельца и версию. | Критично контролировать актуальность docs/spec. | Сопоставить с независимым oracle и точным состоянием. | Умеренные затраты; verification зависит от независимых oracle/checks. |
| AWS Labs AI-DLC workflows | Команда хочет trial harness-neutral structured workflow implementation. | Нужно проверить release, host compatibility, customization и learning curve. | Пересматривать при изменении процесса/границ; закрепить владельца и версию. | Инструкции могут широко влиять; review repository, tools, update path и permissions. | Сопоставить с независимым oracle и точным состоянием. | Open-source repo снижает license barrier, но setup/maintenance/model costs остаются; effectiveness not established here. |

## Разобранная авторская демонстрация

На одной Workbench функции сопоставить стадии требований/дизайна/реализации/проверки из зафиксированного AI-DLC workflow с простым SDD process; отметить обязательные решения человека и где framework может адаптировать детализацию. Прогон не выполнялся.

Ожидаемые выводы — проектируемые критерии walkthrough, не фактические результаты запуска.

## Применение в production

Проверить installed instruction scope, prompts/tools/permissions, agent compatibility, injection surface, update chain, supportability, generated artifacts and test evidence. Репозиторий не равен официальному стандарту AWS для всех команд.

Для любой демонстрации явно указать платформу/harness, prerequisites и статус исполнения. Если команда или API не проверялись на выбранной версии, показывать их как иллюстрацию документации, не как воспроизводимую инструкцию.

## Неопределённости и проверка перед написанием урока

Нужно проверить официальную терминологию/публичный status проекта, pinned release, list supported harnesses, tests и весь lifecycle документации; исходное имя AI-DLC не подтверждает, что это однозначно тот проект, который имел в виду автор curriculum.

Перед подготовкой урока заново проверить текущую версию документации, требования доступа, модель безопасности, доступность функций и точные команды выбранной платформы. Независимое сравнение и эксплуатационные измерения в этом пакете не проводились.
