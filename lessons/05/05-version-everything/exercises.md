# Авторская демонстрация — Р5.05

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

Два Workbench runs используют один task prompt, но второй получил обновлённый tool schema. Без manifest различие ошибочно приписывается модели. Учебная запись:

```json
{
  "task_id": "CLOSE-01",
  "source_commit": "<sha>",
  "spec_digest": "<digest>",
  "prompt_revision": "v2",
  "tool_contract_revision": "v3",
  "model_id": "<available-identifier>",
  "checks": [],
  "execution_status": "not-executed"
}
```

Это собственный формат примера, не SLSA schema. В реальном manifest секрет заменяется контролируемой ссылкой; значение credential не сохраняется. Смена tool schema вызывает review совместимости. Старый manifest позволяет понять входы, но не обещает, что hosted model ещё доступна для replay.

## Критерии разбора

Фиксировать достаточно версий и provenance для объяснимого сравнения/аудита, не сохраняя секреты и лишние данные. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
