# Авторская демонстрация — Р5.03

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

PR Workbench проходит happy-path test закрытия. Но неизвестно, отклоняется ли чужой actor, атомарны ли статус/event и не создаёт ли повтор второй audit record. Реестр выглядит так:

| Обязательство | Пробел | Погашение | Приоритет |
|---|---|---|---|
| Authorization | Нет negative case | Проверка чужой роли/tenant | Высокий по модели доступа |
| Atomicity | Сбой event write не проверен | Failure integration case | Высокий для согласованности |
| Repeat | Есть только один запрос | Повтор и конкурентный запрос | По вероятности дублей/ущербу |
| Текст сообщения | Нет UX-review | Review владельца интерфейса | Отдельно от целостности данных |

Реестр синтетический и не доказывает наличие дефектов. Он показывает, какие утверждения нельзя пока принять. План погашения назначает владельцев, release gate для критичных свойств и сроки пересмотра. После проверки запись закрывается ссылкой на конкретное evidence, а не словом «проверено».

## Критерии разбора

Выявлять накопившиеся непроверенные изменения, оценивать их риск и составлять приоритетный план погашения долга проверки. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
