# Авторская демонстрация — Р5.06

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

Для Workbench изменение domain function разрешено в тестовой ветке. Migration проверяется в disposable DB; production deploy требует отдельной identity и gate. Reviewer связывает checks с итоговым commit.

```text
G1: spec и scope согласованы
G2: unit/architecture checks соответствуют patch
G3: integration проверяет role, repeat и audit failure
G4: независимый review
G5: выпуск в ограниченную среду с recovery plan
```

Отказный сценарий: CI недоступен, а агент предлагает пометить check успешным вручную. Это обход gate, не завершение verification. Корректный исход — blocked с диагностикой или контролируемое исключение по принятой policy. Ожидаемое поведение описано, реального pipeline нет.

## Критерии разбора

Связать риск изменения с независимым evidence, разрешениями, ограничением эффекта и последовательностью допуска. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
