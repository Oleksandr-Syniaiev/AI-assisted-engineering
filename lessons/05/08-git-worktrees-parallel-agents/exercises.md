# Авторская демонстрация — Р5.08

Самостоятельных заданий, сдачи и обязательных артефактов читателя нет. Полный разбор включён в [урок](lesson.md).

## Вход и сценарий

В Workbench task A добавляет фильтр списка, task B — независимое уведомление после согласования API. Для учебного shell-примера нужны Git, существующий repository с commit HEAD, свободные paths и ещё не созданные branches. Команды подходят PowerShell и обычному POSIX shell; здесь не исполнялись:

```shell
git worktree add -b lesson-filter ../wb-filter HEAD
git worktree add -b lesson-notify ../wb-notify HEAD
git worktree list
```

Если HEAD между командами меняется, оба дерева могут получить разный baseline; для настоящего trial используют один заранее зафиксированный SHA. Рабочие processes дополнительно получают разные порты и test DB. Migration не применяется конкурентно к общей dev DB.

После сохранения результата и проверки чистоты дерево удаляют через `git worktree remove`; непереданные changes сначала сохраняют. Force cleanup не входит в демонстрацию. Ожидается локальная изоляция files, а не доказанная isolation всего runtime.

## Критерии разбора

Спроектировать параллельные независимые изменения в отдельных worktrees и изолированных runtime-ресурсах. Проверяемые признаки: указаны исходные данные и scope, объяснён механизм, разобран обычный и отказный случай, владелец решения определён, ожидаемое отделено от реально проверенного.

## Статус исполнения

Документальный разбор: команды, products и agents не запускались. Для будущего исполнения фиксируются source snapshot, versions, изолированные runtime-ресурсы, доступы, бюджет, критерий приёмки и owner. Иллюстративная конфигурация не выдается за проверенную установку.
