# Р1.12 — авторская демонстрация

Материал для чтения. Самостоятельных заданий, обязательных файлов и сдачи нет.

## Разбор: Демонстрация: хорошая передача после дефекта

Плохая запись:

```text
Всё почти готово. Пробелы исправили. Тесты зелёные, продолжи.
```

Неизвестны файл, контракт, команда, ревизия и остаток работы. Получатель может принять старый прогон за новый или исправить уже исправленную функцию.

Разобранный handoff для ситуации Р1.08:

```text
Цель: отклонять пустой после trim заголовок.
Контракт: только string; нормализация до проверки;
" Fix CI " → "Fix CI"; 7 → отказ.
Код-пример: lessons/01/01-agent-basics/practice/title-policy.mjs.
Baseline и corrected сохранены раздельно, первый намеренно ошибочный.
Проверка автора 03.11.2026, Node.js v24.22.1:
baseline 3/4, exit 1; corrected 4/4, exit 0.
Это проверка функции, не браузера и не сохранения.
Следующий шаг: проверить подключение правила в HTTP-стенде.
Ограничение: файлы Р1.01 не переписывать.
```

Это пример передачи существующих фактов, а не отчёт отдельного агента. В рабочем Git-проекте добавляют текущий commit и вывод `git status`. Если изменения не закоммичены, перечисляют их явно: commit не описывает рабочее дерево целиком.

Полезно сохранить ещё нерешённый вопрос и условие остановки: например, «если контракт API расходится с правилом, не менять ожидания без решения». Иначе получатель будет вынужден заново угадывать границы полномочий.
