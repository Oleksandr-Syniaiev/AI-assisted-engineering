## Сценарий демонстрации и примеры для подготовки

На последовательных snapshots покажите working tree → index → commit, unstaged и staged diff, а затем выберите restore для незакоммиченного изменения либо revert для опубликованного commit; перед отменой прочитайте diff.

**Подача:** автор называет snapshot, платформу, prerequisites и границы; показывает наблюдаемые шаги и проверку; маркирует ожидаемые исходы как ожидаемые, а выполненные — только при наличии отчёта. Для команд указать ОС/shell, версии, доступы, prerequisites и статус выполнения.

**Вопрос для разбора:** где заканчивается наблюдаемый факт и начинается инженерная интерпретация? Ответ должен ссылаться на claims-and-evidence в research.md.

## Типичные заблуждения и отказы

- Считать ответ или сообщение «готово» доказательством изменения/корректности.
- Переносить поведение одного продукта или интерфейса на другой без документации.
- Принимать ожидаемый сценарий за фактически исполненный результат.
- Пропускать командный, безопасностный, стоимостный или maintenance trade-off из-за узкого happy path.

## Вопросы для проверки знаний — с ориентирами ответов

### 1. Что показывает status?

Различия состояний и новые отслеживаемые/неотслеживаемые пути; это отправная точка перед review. [SRC-015](https://git-scm.com/docs/git-status)

### 2. Почему обычный diff пуст после add?

Изменение может находиться в index; для него нужен staged diff. [SRC-016](https://git-scm.com/docs/git-diff)

### 3. Что фиксирует add?

Содержимое выбранного файла в момент staging, а не все будущие изменения файла. [SRC-017](https://git-scm.com/docs/git-add)

### 4. Что сохраняет commit?

Подготовленный snapshot; файлы вне него и внешние данные требуют отдельного обращения. [SRC-018](https://git-scm.com/docs/git-commit)

### 5. Когда использовать restore?

Для оговорённого восстановления содержимого в учебной копии после проверки несохранённых изменений; эффект зависит от flags. [SRC-019](https://git-scm.com/docs/git-restore)

### 6. Когда полезен revert?

Когда требуется отменяющий commit с сохранением истории; возможные конфликты нужно разрешить и проверить. [SRC-020](https://git-scm.com/docs/git-revert)

### 7. Как Git связан с доверием к агенту?

Сравнение baseline и результата делает scope reviewable; история сама по себе не доказывает корректность. [SRC-016](https://git-scm.com/docs/git-diff)
