# Р1.01 — практические задания

Уровень: основы agentic coding. Основной маршрут выполняется в браузере или текстовом редакторе без аккаунта и установки агента. Ориентировочное время — 20–30 минут; оценка не пилотировалась.

## Входы

- Урок: lesson.md или index.html.
- Учебный trace: шесть записей из раздела 5 урока.
- Код: practice/title-policy.mjs; oracle: practice/checks.mjs.
- Evidence: practice/verification.md.
- Шаблоны: practice/agent-loop-map.template.md и practice/task-contract.template.md.

Случай относится к фрагменту предлагаемого Engineering Workbench. Полное приложение не предполагается. Не изменяйте исходные тесты ради зелёного результата.

## Задание A. Аудит trace

1. Для каждой из шести записей укажите категорию: намерение, действие, наблюдение или вывод.
2. Запишите инструмент или «не выполнялось». Если trace говорит о результате инструмента, явно отметьте, что это смоделированная запись, а не новый локальный запуск.
3. Для каждой записи разделите подтверждённое, предполагаемое и неизвестное.
4. Найдите минимум два расхождения между отчётом исполнителя и доступными evidence.
5. Назовите дополнительный check, которого не хватает внутри trace.
6. Сформулируйте решение: какую часть результата уже можно оценить, а что пока принимать нельзя.

Артефакт: заполненный agent-loop-map.md. В HTML есть интерактивная классификация; текстовый файл остаётся основным переносимым результатом.

### Критерии приёмки

- Все шесть записей разобраны, для каждой есть основание классификации.
- В записи 3 выявлено обобщение проверки пустой строки на пробельный ввод.
- В записи 6 выявлены неподтверждённые API и БД checks.
- Отмечен отсутствующий в trace запуск corrected-suite.
- Локальное измерение автора и смоделированный журнал не смешаны.

### Ориентир проверки

| Запись | Основная категория | Пояснение |
|---|---|---|
| 1 | Намерение | Обещание проверки ещё не является её выполнением |
| 2 | Наблюдение | Доступен результат чтения; само обращение к инструменту — предшествующее действие |
| 3 | Вывод | Обобщение не подтверждено пробельным случаем |
| 4 | Наблюдение | Показаны результаты конкретного test runner; не результат всей системы |
| 5 | Действие | Подготовлено изменение, для его приёмки ещё нужен check |
| 6 | Вывод | Отчёт содержит неподтверждённые утверждения |

Допустимо разделить запись 2 или 4 на действие и наблюдение, если вы явно обозначили обе части. В интерактивном задании выбирается основная категория всей записи.

## Задание B. Ограниченное поручение

На основе task-contract.template.md составьте поручение на объяснение baseline без изменений. Не предполагается обязательное исполнение живым агентом: задача этого урока — сформулировать проверяемый контракт.

Контракт должен содержать:

- цель: объяснить, почему пробельный title принят;
- входы: конкретные функции и oracle;
- scope: чтение; без установки, записи и внешних действий;
- критерии: разбор пустого, пробельного и корректного title, ссылки на условия кода;
- evidence: что было прочитано, что запускалось, что не проверялось;
- stop condition: перечислить недостающие данные/права вместо выдуманного результата.

Артефакт: task-contract.md. Скачивание из HTML сохраняет текст локально по явному действию читателя. Поле не отправляется в сеть и не является подключением к модели; перезагрузка страницы сбрасывает несохранённый ввод.

## Задание C. Распределение ответственности

Продвинутый вариант: распределите поиск причины, исполнение фиксированных cases и согласование бизнес-правила между агентом, скриптом и инженером. Для каждого укажите вход, выход, failure mode и независимую проверку.

Критерий приёмки: три обоснованные границы и один сценарий, в котором расширение автономности увеличивает стоимость review. Например, агенту поручили «улучшить валидацию», он изменил формат API и ожидания тестов. Для принятия понадобится дополнительное согласование, хотя узкое исправление его не требовало.

## Необязательное воспроизведение кода

Рабочая директория — папка lessons/01/01-agent-basics. Нужен установленный Node.js; пример проверен на v24.22.1, другие версии не испытывались. Внешних зависимостей нет.

```shell
node --version
node --test practice/baseline.test.mjs
node --test practice/corrected.test.mjs
```

Ожидание: baseline падает на whitespace-only, corrected проходит четыре cases. Сохраните фактические counts и exit codes; не подменяйте наблюдение ожидаемым выводом. Повторять запуск в production-среде или с реальными пользовательскими данными не требуется.
