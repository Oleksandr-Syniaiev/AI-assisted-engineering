# Установить агента и выполнить первый запуск

Первый результат — понятный доступ к проекту, а не большое изменение.

**Р1.03 · Основы · 40–60 минут.** Нужны [Р1.01](../01-agent-basics/index.html), [Р1.02](../02-tool-selection/index.html); пути объяснены в [Р1.04](../04-files-editor-terminal/index.html). Команды: Windows и PowerShell. Установка и вход показаны по документации; при подготовке урока они не выполнялись.

## Результат урока

Вы сможете отличить установленный клиент от авторизованного, открыть проект и задать первое поручение только на чтение. Также сможете локализовать ошибку: команда не найдена, вход не завершён, открыт неверный каталог или действие запрещено.

## Почему «программа открылась» недостаточно

У первого запуска четыре независимых условия. Операционная система должна находить исполняемый файл. Клиент должен иметь поддерживаемый способ доступа к сервису. Рабочий каталог должен указывать на нужный проект. Разрешения должны позволять необходимые действия. Приветственный экран сам по себе этого не доказывает.

Используем Codex CLI как конкретный маршрут. Если агент уже работает в настольном приложении, переустанавливать его ради урока не нужно: важны те же проверки каталога, доступа и границ.

## Что устанавливается и что остаётся отдельным

**Runtime** исполняет код приложения. Для учебного стенда это Node.js. **Менеджер пакетов** устанавливает программные пакеты; npm обычно поставляется с Node.js. **Клиент агента** связывает запросы с моделью и инструментами. Установка клиента не подготавливает автоматически любой открытый проект.

**Авторизация** подтверждает право клиента работать от имени учётной записи. Она не равна разрешению читать произвольные документы или отправлять изменения в GitHub. Сеть для обращения к модели и доступ команды к интернету тоже могут регулироваться отдельно. [SRC-003](https://learn.chatgpt.com/docs/agent-approvals-security)

```text
PowerShell находит codex → клиент запускается → вход в сервис
                       → каталог и разрешения → чтение проекта
```

## Подготовка: посмотреть окружение

Предусловия документального примера: Windows, PowerShell, установленный Node.js с npm, интернет для установки и доступная учётная запись. Для локального стенда проверена Node.js v24.22.1; это не утверждение о минимальной версии клиента.

```powershell
node --version
npm --version
Get-Command node
Get-Command npm
Get-Location
```

Первые команды показывают версии и пути программ, последняя — текущий каталог. Выводы должны относиться к одной среде. Node.js в Windows и Node.js внутри WSL — разные установки. Смешивание этих маршрутов затрудняет диагностику.

Если `node` не найден, проблема возникает до вызова AI. Сначала устанавливают поддерживаемый Node.js по официальной инструкции и открывают новый терминал. `PATH` — список каталогов для поиска команд; старый процесс терминала может использовать старое значение.

## Установка и вход: документальный маршрут

Официальный changelog показывает установку npm-пакета `@openai/codex`. Ниже тот же пакет указан без версии: результат зависит от даты установки. Для воспроизводимого командного окружения версию фиксируют после проверки совместимости. [SRC-033](https://learn.chatgpt.com/docs/changelog)

```powershell
npm install --global @openai/codex
Get-Command codex
codex --version
```

Установка изменяет пользовательское окружение и требует сети. Ожидаемый результат — доступная команда `codex`; успешная установка на компьютере читателя здесь не заявлена. При блокировке npm-shim в PowerShell можно проверить `Get-Command codex.cmd` и вызвать `codex.cmd --version`. Это проверка конкретного файла, а не предложение отключить системную политику исполнения.

После перехода в каталог проекта запускают `codex`. При первом запуске клиент предлагает вход с ChatGPT или другой доступный способ. Условия доступа зависят от продукта и учётной записи. [SRC-002](https://learn.chatgpt.com/docs/codex/cli)

Коды входа и токены вводят в предусмотренном окне авторизации. Их не добавляют в промпт, README и скриншот отчёта. Ошибку входа исправляют в контуре авторизации, а не изменением приложения.

## Первое поручение: проверить видимость проекта

Из корня курса в PowerShell:

```powershell
Set-Location -LiteralPath 'lessons/01/demo-workbench'
Get-ChildItem
codex
```

Ожидаются `server.mjs`, `client.html`, `policy.mjs` и `workbench.test.mjs`. Если структура другая, сначала исправляют путь. В клиенте выбирают доступ только на чтение, если он доступен в текущей версии, и отправляют запрос:

```text
Изучи только server.mjs, client.html и policy.mjs.
Объясни путь заявки от формы до файла.
Укажи функцию проверки заголовка и место записи данных.
Не изменяй файлы, не устанавливай пакеты и не отправляй данные наружу.
Перечисли прочитанные файлы и непроверенные предположения.
```

Хороший результат связывает описание с `validateTitle`, обработчиком `POST /api/requests` и `save(rows)`. Фраза «вижу проект» без привязки к коду этого не доказывает. Здесь приведён ожидаемый разбор: реальная агентная сессия не запускалась.

Текст запрета объясняет цель, но не заменяет технических ограничений. Если клиент не позволяет нужное ограничение, инженер учитывает это до выдачи доступа. После чтения состояние файлов должно остаться прежним; в Git-проекте это проверяют через `git status` и `git diff` из Р1.07.

## Диагностика без случайных переустановок

| Симптом | Слой проблемы | Следующий узкий шаг |
|---|---|---|
| Команда не найдена | Shell не нашёл клиент | `Get-Command`, PATH, новый терминал |
| Клиент работает, вход не проходит | Доступ к сервису | Метод входа и сообщение сервиса |
| Агент обсуждает чужие файлы | Каталог или контекст | Проверить путь и назвать входы |
| Чтение доступно, запись запрещена | Граница полномочий | Сопоставить разрешение с задачей |
| Тест не находит Node.js | Среда команды | `node --version` именно в ней |

Переустановка всего сразу скрывает причину. Узкие проверки позволяют сохранить работающий setup и исправить только сломанный слой.

## Production и альтернативы

В команде фиксируют ОС, версию клиента, способ входа, корень проекта, runtime и точную команду теста. Учётные данные остаются в управляемом хранилище, а не в инструкции установки. Обновление клиента сначала проверяют на небольшом сценарии: настройки и разрешения могут меняться.

| Критерий | CLI | Расширение IDE | Настольное приложение |
|---|---|---|---|
| Применение | Команды и автоматизация | Код рядом с diff | Задачи через UI |
| Освоение | Shell и PATH | Редактор и настройки | Навигация и доступ |
| Внедрение | Версия бинарника | Версия расширения | Версия приложения |
| Сопровождение | Setup и скрипты | Совместимость редактора | Обновления и политики |
| Безопасность | Права команд и файлов | Workspace и полномочия | Проект и разрешения |
| Проверяемость | Вывод команд | Diff и логи | Отчёт плюс просмотр файлов |
| Стоимость | Доступ и подготовка | Доступ и интеграция | Доступ и освоение UI |

Это сравнение маршрутов, не обещание возможностей любого продукта.

## Вопросы с объяснёнными ответами

### 1. `codex --version` доказывает вход?

Нет. Он показывает доступность локального клиента. Авторизация проверяется отдельно.

### 2. Зачем новый терминал после установки?

Уже работающий процесс может не получить обновлённые переменные окружения. Новый перечитывает их при запуске.

### 3. Можно исправить PATH сменой модели?

Нет. PATH относится к поиску локальных команд и проверяется в той же оболочке.

### 4. Почему первое поручение только на чтение?

Оно проверяет контекст и доступ, не смешивая их с риском изменения кода.

### 5. Достаточно фразы «не изменяй файлы»?

Это инструкция о намерении. Техническую границу задают настройки полномочий клиента.

### 6. Можно сохранять токен в setup-инструкции?

Нет. Инструкция описывает получение доступа, а не публикует учётные данные.

### 7. Что здесь проверено исполнением?

Локальный стенд проверен в [журнале](../demo-workbench/verification.md). Установка клиента, оплата и вход не выполнялись.

## Главное и следующий шаг

Первый запуск проверяет клиент, доступ, каталог и права. Далее [Р1.04](../04-files-editor-terminal/index.html) объясняет файлы и процессы, от которых зависит этот маршрут.
