# Папка, файл, редактор и терминал

Одинаковая команда работает по-разному, если изменился её контекст.

**Р1.04 · Основы · 35–50 минут.** Достаточно [Р1.01](../01-agent-basics/index.html). Этот урок можно прочитать перед Р1.02–Р1.03. Примеры: Windows и PowerShell.

## Результат урока

Вы сможете прочитать путь, определить рабочий каталог, различить терминал и shell, объяснить разницу между сохранением файла и работающим процессом. Эти понятия позволяют понимать действия агента, а не воспринимать командную строку как ритуал.

## Почему это влияет на результат

Инженер открывает новый терминал и запускает знакомый тест. Вчера он проходил, сегодня «файл не найден». Код мог не измениться: вчера команда выполнялась в папке примера, сегодня — в корне курса. Относительный путь указывает на разные места.

AI не отменяет эту зависимость. Если агент назвал правильную команду, но выполнил её не там, вывод может не относиться к проверяемому примеру. Поэтому отчёт о запуске включает рабочий каталог вместе с командой.

## Файл, папка и путь

**Файл** хранит байты: текст программы, настройки, изображение. Расширение `.mjs` помогает программе выбрать способ обработки, но не гарантирует содержимое. **Папка**, или каталог, группирует записи файловой системы. Папка `project-final` сама по себе не является ни резервной копией, ни признаком готовности.

**Абсолютный путь** задаёт местоположение от корня файловой системы: например, `C:\work\course\lessons\01\demo-workbench\server.mjs`. **Относительный путь** считается от исходной папки: `lessons/01/demo-workbench/server.mjs` из корня курса. `.` означает текущую папку, `..` — родительскую.

```text
course/                     ← корень проекта
  lessons/
    01/
      demo-workbench/
        server.mjs          ← программа сервера
        client.html         ← документ для браузера
        policy.mjs          ← правило заголовка
```

Из `demo-workbench` путь `policy.mjs` корректен. Из корня курса тот же текст указывает на другой файл, которого, возможно, нет. Это первая проверка при `ENOENT` — распространённом обозначении отсутствующего файла или каталога.

## Редактор, терминал, shell и процесс

**Редактор** показывает и изменяет текст. **Терминал** предоставляет окно ввода и вывода. **Shell**, или командная оболочка, разбирает строку и запускает программы; здесь это PowerShell. Bash — другая оболочка со своим синтаксисом. Команда с `$env:PORT` не переносится в Bash простым копированием.

**Процесс** — запущенная программа с памятью, переменными окружения и рабочим каталогом. Терминал может быть встроен в редактор, но его каталог не обязан совпадать с папкой выделенного файла. Открытие вкладки `server.mjs` не запускает сервер.

```text
Редактор → сохраняет текст на диск
Shell    → запускает node server.mjs
Node.js  → читает программу и обслуживает HTTP
Браузер  → обращается к работающему серверу
```

Сохранение файла и обновление работающего процесса — разные события. В стенде нет автоматической перезагрузки сервера: после изменения серверного кода процесс останавливают и запускают заново. Иначе браузер обращается к старому коду, хотя редактор уже показывает новый.

## Разобранная последовательность просмотра

Предусловия: PowerShell в корне этого курса, доступный Node.js. Конкретный абсолютный путь у читателя будет другим. Команды просмотра не изменяют содержимое проекта.

```powershell
Get-Location
Get-ChildItem -LiteralPath 'lessons/01/demo-workbench'
Resolve-Path -LiteralPath 'lessons/01/demo-workbench/policy.mjs'
Get-Content -LiteralPath 'lessons/01/demo-workbench/policy.mjs'
```

`Get-Location` отвечает на вопрос «откуда считаются относительные пути». `Get-ChildItem` показывает записи каталога. `Resolve-Path` позволяет увидеть разрешённый путь. `Get-Content` читает содержимое. `-LiteralPath` передаёт путь буквально, без раскрытия шаблонов. Назначение текущего местоположения документировано Microsoft. [SRC-010](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-location?view=powershell-7.5)

Теперь переход:

```powershell
Set-Location -LiteralPath 'lessons/01/demo-workbench'
Get-Location
node --test workbench.test.mjs
$LASTEXITCODE
```

После перехода префикс `lessons/01/demo-workbench/` не нужен. `$LASTEXITCODE` относится к последней внешней программе, здесь Node.js. Нулевой код означает успешное завершение по правилам программы; он не доказывает все свойства приложения. Проверенный запуск этого набора описан в журнале стенда.

Путь с пробелами заключают в кавычки: `Set-Location -LiteralPath 'C:\work\AI assisted engineering'`. Они сообщают оболочке, что это один аргумент, но не проверяют существование папки.

## Как читать ошибку по слоям

| Наблюдение | Вероятный слой | Что проверить |
|---|---|---|
| `node` не распознан | Поиск команды | `Get-Command node`, PATH |
| `Cannot find module` с путём | Входной файл или импорт | Каталог, имя и регистр пути |
| `EACCES` | Доступ к действию | Операцию, путь или адрес и политику среды |
| `EADDRINUSE` | Сетевой процесс | Не работает ли другой сервер на порту |
| Правка не проявилась | Жизненный цикл процесса | Сохранение и перезапуск |

Сообщение — наблюдение, а причина пока гипотеза. Например, `EACCES` при соединении с localhost не доказывает отсутствие прав на файл. Сначала читают операцию и адрес в сообщении.

## Production и альтернативы

В команде инструкции фиксируют рабочую папку, платформу и версии. Скрипт, который работает только из случайного каталога автора, дорого сопровождать. В сервере стенда путь к данным вычисляется от самого модуля, а не от папки терминала. Поэтому оба документированных способа запуска обращаются к одному файлу данных.

| Критерий | Проводник и редактор | Терминал | Скрипт проекта |
|---|---|---|---|
| Применимость | Структура и текст | Диагностика и запуск | Устойчивые последовательности |
| Освоение | Визуальная навигация | Команды и аргументы | Команды внутри скрипта |
| Внедрение | Открыть папку | Выбрать shell и каталог | Описать точку запуска |
| Сопровождение | Ручные шаги | История команд ненадёжна | Версионировать скрипт |
| Безопасность | Верный выбор файла | Права запускаемых команд | Обзор до запуска |
| Проверяемость | Видно содержимое | Вывод и код завершения | Одинаковый вход в проверку |
| Стоимость | Повторять вручную | Освоить диагностику | Подготовка и поддержка |

Для агента полезна такая же дисциплина: назвать рабочий каталог, ограничить область чтения, сохранить вывод. Отчёт «запустил» без команды и места невозможно уверенно повторить.

## Вопросы с объяснёнными ответами

### 1. Почему `policy.mjs` находится только из одной папки?

Это относительный путь. Его значение зависит от рабочего каталога, а не от последнего файла в редакторе.

### 2. Встроенный терминал всегда находится в папке открытого файла?

Нет. Проверяют каталог самого shell. Размещение окна внутри редактора этого не гарантирует.

### 3. Сохранение серверного файла обновляет процесс?

Только при наличии механизма перезагрузки. В нашем стенде его нет, поэтому нужен перезапуск.

### 4. Зачем сохранять команду вместе с каталогом?

Чтобы другой инженер проверил тот же входной файл. Одинаковый текст команды может относиться к другому проекту.

### 5. Почему не стоит смешивать PowerShell и Bash?

Они по-разному разбирают команды и переменные. Сначала выбирают платформу, затем переводят синтаксис.

### 6. Что означает нулевой exit code?

Программа завершилась успешно по своей логике. Полнота проверки зависит от её содержания.

### 7. Остановка сервера удаляет данные?

Она завершает процесс. Сохранённые файлы остаются, данные только в памяти исчезают. Это различие понадобится далее.

## Главное и следующий шаг

Путь задаёт вход, shell запускает программу, процесс исполняет её, редактор хранит текст. В [Р1.05](../05-application-components/index.html) проследим, как процессы и файлы образуют приложение.
