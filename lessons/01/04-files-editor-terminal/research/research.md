## 2. Исследовательские вопросы и ответы

Вопросы раздела сформулированы до сбора источников: проблема, определение, механизм, альтернативы, проверяемость, production-риски и зависимости. Ниже — конкретизация для этой темы. **Ответы являются синтезом и инженерной интерпретацией**, кроме прямо выделенных Verified claims в разделе 7. Ссылка означает опору на указанный механизм/ограничение, а не доказательство эффективности предложенной демонстрации.

### Q1. Почему команда работает в одном окне и не работает в другом?

Различаться могут shell, cwd, PATH и окружение; визуально похожее окно не означает одинаковые условия. [SRC-009](https://code.visualstudio.com/docs/terminal/basics)

### Q2. Что показывает Get-Location?

Текущую PowerShell location; для упражнения использовать файловый provider. [SRC-010](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-location?view=powershell-7.5)

### Q3. Достаточно открыть файл в редакторе?

Нет: активный файл не доказывает, что terminal находится в его каталоге. [SRC-009](https://code.visualstudio.com/docs/terminal/basics)

### Q4. Как обращаться с пробелами в пути?

Передавать путь единым аргументом и использовать правила quoting выбранного shell; не переносить синтаксис между PowerShell и Bash. [SRC-009](https://code.visualstudio.com/docs/terminal/basics)

### Q5. Где находится приложение во время запуска?

Исходник лежит на диске, процесс выполняется в окружении; закрытие вкладки файла не эквивалентно остановке процесса. [SRC-009](https://code.visualstudio.com/docs/terminal/basics)

### Q6. Как проверить найденный путь?

Сопоставить полный путь из редактора и cwd терминала; это проверка среды, а не доверие к названию вкладки. [SRC-010](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-location?view=powershell-7.5)

### Q7. Зачем это production-инженеру?

Логи инцидента и воспроизведение команды должны содержать cwd и shell, иначе расследование может происходить в другом проекте. [SRC-009](https://code.visualstudio.com/docs/terminal/basics)

## 3. Терминология

Терминал предоставляет интерфейс ввода/вывода; shell интерпретирует команды. Относительный путь зависит от working directory. Workspace редактора может содержать несколько корней.

Не считать названия интерфейсов разных продуктов эквивалентными. Общая терминология уточняется перед drafting; отдельного GLOSSARY.md пока нет.

## 4. Механизмы и архитектурный разбор

1. Проследить путь: editor save → файл на диске → shell разрешает команду → процесс читает относительный путь.
2. Показать схему двух папок с одинаковым README, чтобы ошибку нельзя было скрыть совпадающим именем.
3. Развести stdout/stderr и код завершения на уровне наблюдения; для Bash и PowerShell не смешивать переменные статуса.

Это план объяснения механизмов на учебном примере, а не утверждение о внутреннем устройстве всех инструментов. Для diagram и demonstrations использовать только наблюдаемые границы и явно обозначенные допущения.

## 6. Production engineering

В monorepo имя папки не определяет границу пакета. Runbook должен указывать рабочую папку и shell; команды из чужого issue нельзя выполнять без понимания эффекта. Изменение env в одном terminal не гарантирует его наличие в другом.

До приёмки результата сопоставить scope, актуальный snapshot, diff и проверки. Отчёт о действиях не подменяет evidence; стоимость включает человеческую проверку. За технические права отвечает конфигурация среды, за решение о выпуске — назначенный владелец.

## 9. Авторская практическая демонстрация

**Сценарий:** **Платформа примера:** PowerShell 7.x, путь с пробелами; показ команд ниже иллюстративный, локально в рамках этого исследования не запускался.

```powershell
Get-Location
Get-Item -LiteralPath 'C:\work\AI assisted engineering\app\package.json'
Set-Location -LiteralPath 'C:\work\AI assisted engineering\app'
Get-Location
```

Автор сопоставляет полный path файла в редакторе, cwd процесса shell и каталог, из которого запускается команда. Затем показывает, что вкладка файла остаётся открытой при переключении terminal на другой cwd; имя вкладки не задаёт рабочий каталог. Разбор требует указать результат `Get-Location` перед любым относительным путём.

**Статус и границы:** это сценарий будущего рассказа/показа. Полное приложение Engineering Workbench остаётся кандидатом; scaffold и end-to-end запуск не подтверждены. Отдельно указанное фактическое evidence относится только к конкретному ограниченному примеру и не переносится на приложение.

**Платформа и prerequisites:** до исполнения демонстрации указать целевую ОС/shell, версии, точный snapshot, необходимые fixtures, доступы, сеть и последствия команд. Продуктовые installer/flags и billing проверять по текущей документации выбранного продукта. Команды в примере с явной пометкой «иллюстративный» требуют выполнения автором до публикации урока.

**Ожидаемое и фактическое:** ожидаемые наблюдения задают учебный сценарий. Фактическим результатом считать только наблюдение из зафиксированного локального verification-отчёта; обзор документации или проектирование сценария не означает исполнение. Демонстрация предназначена для объяснения материала и не требует сдачи работы от читателя.
