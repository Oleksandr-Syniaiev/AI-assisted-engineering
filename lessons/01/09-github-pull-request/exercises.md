# Р1.09 — авторская демонстрация

Материал для чтения. Самостоятельных заданий, обязательных файлов и сдачи нет.

## Разбор: До публикации: проверить состав и адрес

Предусловия: отдельный учебный проект уже является Git-репозиторием с baseline commit. Корень этого курса не нужно инициализировать ради чтения урока. В PowerShell из корня такого проекта:

```powershell
git status --short
git remote -v
git branch --show-current
git log -1 --oneline
```

Проверяют незавершённые изменения, адреса fetch/push и текущую ветку. До первого push читают состав истории и файлов: `.env`, токены, рабочие данные и личные документы не должны отправляться случайно. Добавление файла в `.gitignore` не удаляет его из существующей истории.

Если remote отсутствует, сначала создаётся пустой репозиторий в нужной учётной записи или организации с выбранной видимостью. Существующий remote не заменяют вслепую. Ссылка и метод авторизации должны соответствовать политике команды.

Документальный пример добавления адреса:

```powershell
# OWNER и REPOSITORY — заменяемые обозначения, не готовый URL.
git remote add origin https://github.com/OWNER/REPOSITORY.git
git remote -v
```

Команда применяется только при отсутствии `origin`. Если серверный репозиторий уже содержит отдельную историю, нельзя принуждать push: сначала выясняют расхождение. Для пустого удалённого репозитория и проверенной локальной ветки `main` первая публикация выглядит как `git push -u origin main`. Это внешнее действие: до него нужны выбранная видимость, доступ и просмотр состава истории. Здесь оно не выполнялось. Если ветка называется иначе, её имя сначала проверяют, а не переименовывают случайно. Первую публикацию отдельно описывает [GitHub Docs](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).
