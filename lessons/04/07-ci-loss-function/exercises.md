# Авторская демонстрация — Р4.07

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Для Workbench unit job проверяет state policy, integration job — authorization и согласованность audit event. Намеренный запретный `open → closed` должен давать отказ. Но pipeline может быть зелёным, если test был пропущен или workflow не запустился.

```text
неизменный oracle → воспроизведение дефекта → минимальная правка
→ те же checks → проверка обязательности gate → review итогового commit
```

Если агент меняет expected вместо реализации, сигнал теряет смысл. Reviewer проверяет diff тестов, причины skips и источник статуса. Flaky test нельзя лечить бесконечным retry до первого зелёного результата: это скрывает вероятность отказа.

## Как оценивать разбор

Результат: Строить CI как измеримый контур обратной связи и допуска, не приписывая ему автоматическое обучение модели.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
