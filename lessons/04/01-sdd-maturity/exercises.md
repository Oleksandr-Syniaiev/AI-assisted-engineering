# Авторская демонстрация — Р4.01

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Для Workbench рассмотрим CLOSE-01: закрывать `in_progress` может назначенный исполнитель. В кратком issue это одна фраза. В feature spec добавляются запрещённая роль, неверное состояние и ожидаемая ошибка без изменения данных. В поддерживаемом процессе изменение роли администратора инициирует review spec, tests и потребителей API.

```text
CLOSE-01 → authorization component → role integration test → owner review
CLOSE-02 → transition policy → negative state test → результат на commit
```

Если положительный test есть, а отрицательный отсутствует, покрытие требования неполно. Объём документа не закрывает этот пробел. Ожидаемый результат разбора — видимая связь требования и проверки, без утверждения об исполнении.

## Как оценивать разбор

Результат: Различать intent, design, implementation и evidence; выбирать достаточную формализацию вместо максимального числа документов.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
