# Авторская демонстрация — Р4.17

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

В Workbench существует правило закрытия только исполнителем. Change добавляет роль администратора. В пакете нужно показать изменённый критерий и неизменяемые свойства: прежний tenant scope, отказ чужому пользователю, повтор и audit consistency.

```text
change intent: расширить actor set для CLOSE-01
delta: разрешить administrator в своей tenant boundary
preserve: C2 state policy, C3 idempotency, C4 audit
verification: role matrix + regression cases
```

После реализации reviewer проверяет, что новые specs действительно отражают решение. Если change архивирован, но current spec осталась старой, обнаружен drift. Если текущий код расходится со spec по другой причине, не следует незаметно включать это расхождение в scope изменения.

Структура здесь концептуальная; точные generated directories и commands берутся из pinned release. CLI не запускался, archive и code reconciliation не наблюдались в рабочем приложении.

## Как оценивать разбор

Результат: Различать текущую спецификацию и предлагаемое изменение; проверять reconciliation после реализации, а не считать архив evidence корректности.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
