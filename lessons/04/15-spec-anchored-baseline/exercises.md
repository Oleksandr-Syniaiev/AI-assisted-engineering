# Авторская демонстрация — Р4.15

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Учебный baseline Workbench содержит четыре критерия: роль исполнителя, допустимое состояние, повтор по key и согласованный audit event. Инженер оформляет компактный spec, агент готовит scoped patch, checks проверяют свойства, reviewer принимает итоговый commit.

```text
C1 → authorization → integration role cases
C2 → transition policy → positive/negative state cases
C3 → deduplication → repeat/concurrent cases
C4 → persistence → failure/transaction cases
```

Для альтернативного toolkit стартуют с той же исходной версии без hidden advantage в виде заранее сгенерированного design. Если инструмент не поддерживает нужную среду, результат записывается как ограничение доступности, а не нулевая корректность алгоритма. Никаких сравнительных запусков здесь не было.

## Как оценивать разбор

Результат: Определять честный baseline и единые критерии до знакомства с обещаниями конкретных инструментов.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
