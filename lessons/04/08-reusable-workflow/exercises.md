# Авторская демонстрация — Р4.08

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Превратим единичный change Workbench в путь «заявка → spec → patch → verification → review». Вход содержит task ID, source commit, scope и ссылки на criteria. Выход — diff, версия spec, результаты реально выполненных checks и неизвестное.

```text
stage: verify
input: reviewed patch at commit H
success: соответствующие checks завершены и отчёты привязаны к H
failure: missing environment → blocked с диагностикой
resume: сверить H и состояние внешних действий
```

Если resumed run получил новый commit, старый отчёт не переносится как evidence без повторной оценки. Если verification runner недоступен, workflow не должен записывать completed только потому, что patch создан. Это учебная state model, не синтаксис конкретного engine.

## Как оценивать разбор

Результат: Превращать одноразовую процедуру в контрактный, версионируемый и возобновляемый процесс.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
