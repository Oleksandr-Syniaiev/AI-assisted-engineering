# Авторская демонстрация — Р4.19

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Для Workbench простая генерация spec может подготовить CLOSE-01..04, но не даёт execution evidence. Если выбран расширенный flow, добавляются этапы планирования, запуска и walkthrough. Их надо сравнить по одинаковым критериям, а не по числу папок.

```text
Simple evaluation: получен ли согласованный contract?
Execution-flow evaluation: получен ли contract + принятый patch + checks?
Общее: actors, state, повтор, audit и независимый oracle.
```

Если сравнивать полный execution-flow с Simple по количеству реализованного кода, единица сравнения изначально несправедлива. Сначала выравнивают scope, затем добавляют недостающие стадии одинаковым способом.

Команды installer из README в урок не превращаются в проверенный tutorial. Npx, расширения и framework не запускались; portability и writes установщика не проверены.

## Как оценивать разбор

Результат: Идентифицировать проект и выбранный flow, сравнивать одинаковый scope и не подменять документацию испытанием.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
