# Авторская демонстрация — Р4.11

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Сравним `execute_sql(query)` и предметный `close_request`. Второй принимает request ID, expected version и idempotency key; tenant и actor берутся из trusted identity context, а не безусловно из модельного текста.

```json
{
  "request_id": "REQ-17",
  "expected_version": 4,
  "idempotency_key": "close-req17-attempt1"
}
```

Иллюстративный payload не является готовой API-schema. Если version уже 5, возвращается conflict без скрытого перезаписывания. Если actor не имеет права, запрос отклоняется независимо от пояснений агента. При timeout исход проверяется по idempotency key прежде повтора. Широкий admin tool может оставаться для инженера в отдельном контролируемом контуре, но не нужен агенту этой задачи.

## Как оценивать разбор

Результат: Ограничивать capability на trusted boundary, одновременно сохраняя пригодность tool для реальной задачи.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
