# Авторская демонстрация — Р4.04

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Разберём AUTO-01: «закрыть старые requests». Вопросы: старше чего, в каком часовом поясе, во всех tenants ли, какие состояния допустимы? Затем — что делать с заявкой, которую пользователь обновил одновременно с scheduler.

Для учебного контракта owner выбирает: только `in_progress`, возраст от последнего изменения по UTC, согласованный threshold, отдельная tenant scope. Непосредственно перед записью проверяется версия. Повтор не создаёт дубликат события.

```text
AUTO-01a: age >= threshold, состояние in_progress → кандидат
AUTO-01b: версия изменилась после выбора → пропустить/переоценить
AUTO-01c: другой tenant → не читать и не менять
```

Это выбранные решения синтетического примера. Их нельзя выдавать за фактическую политику курса или клиента. Ожидаемый результат — критерии, позволяющие написать tests без домысливания.

## Как оценивать разбор

Результат: Преобразовывать неоднозначность spec в решение с owner и проверяемые критерии до кодирования.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
