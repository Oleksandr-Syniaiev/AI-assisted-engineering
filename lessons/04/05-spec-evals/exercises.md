# Авторская демонстрация — Р4.05

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

В spec CLOSE-01 есть описание успешного закрытия, но нет негативного случая для чужого исполнителя. Структурный check подтверждает только наличие ID и link. Модельный reviewer предлагает finding: «не определена неавторизованная попытка», указывает фрагмент и последствия. Owner подтверждает требование, после чего добавляется AUTH-NEG-01.

```text
case: missing-unauthorized-transition
expected_finding: отсутствие явного критерия отказа
not_acceptable: «спецификация идеальна» без разбора scope
```

Для проверки grader нужны и документы без этого дефекта: иначе система, всегда заявляющая проблему, получит ложную видимость успеха. Считайте false positives/negatives. Наличие правильного finding не доказывает, что API реализует запрет.

## Как оценивать разбор

Результат: Выбирать grader по свойству, проверять его на ошибочных и корректных примерах и не смешивать spec-eval с implementation-evidence.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
