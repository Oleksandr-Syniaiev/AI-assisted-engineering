# Авторская демонстрация — Р4.03

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Для закрытия Workbench exposed tool принимает request ID, ожидаемую версию и idempotency key. Псевдокод:

```text
пока бюджет доступен:
  получить решение модели
  проверить имя tool, аргументы и полномочия
  если действие чувствительное: получить approval
  выполнить с timeout и idempotency key
  сохранить результат и trace
  если цель подтверждена: завершить
при исчерпании лимита: сохранить checkpoint и остановиться
```

При timeout после отправки записи сначала выясняется исход по ключу/операции. Слепой retry с новым ключом может создать второе событие. При отказе approval действие не выполняется. Это архитектурный разбор, не код выбранного SDK.

## Как оценивать разбор

Результат: Разделять решение модели и технический контроль; проектировать отмену, retry и восстановление до расширения автономности.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
