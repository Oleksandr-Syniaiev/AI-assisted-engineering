# Авторская демонстрация — Р4.06

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Для Workbench сравним два намерения. Первое — проверить сообщение commit; этому подходит `commit-msg`. Второе — запретить tool запись вне разрешённого каталога; Git hook не видит все shell/file действия и недостаточен.

```text
Контракт agent hook:
вход: имя действия, target, identity и args
проверка: target в allowlist, credentials подходят scope
выход: deny с причиной либо allow
сбой/timeout: политика для чувствительной записи — fail closed
```

Это псевдоконтракт без выдуманной JSON-schema конкретного клиента. Для истинного enforcement ещё проверяют, нельзя ли вызвать ту же операцию другим tool. Политика отказа выбирается по риску, а не предполагается одинаковой во всех продуктах.

## Как оценивать разбор

Результат: Выбирать hook по событию и границе действия, отдельно проверяя block, timeout и bypass.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
