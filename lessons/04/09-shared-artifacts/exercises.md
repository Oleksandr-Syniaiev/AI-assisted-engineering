# Авторская демонстрация — Р4.09

Самостоятельных заданий и сдачи нет. Полный разбор включён в [урок](lesson.md).

## Сценарий и входы

Reviewer Workbench получает test report, созданный до изменения authorization. В файле написано passed, но source commit не совпадает с текущим patch. Приёмка должна отклонить перенос evidence.

```json
{
  "schema_version": 1,
  "kind": "verification-report",
  "task_id": "CLOSE-01",
  "source_commit": "<exact-commit>",
  "status": "not-executed",
  "checks": []
}
```

Это учебный JSON, не стандарт GitHub или SDK. Значение not-executed честно отражает отсутствие запуска. В реальной реализации checksum, подпись и ACL выбираются по threat model. При публикации нового report старый не перезаписывается бесследно: сохраняется lineage и причина supersession.

## Как оценивать разбор

Результат: Передавать результат вместе с версией, происхождением и границей доказательности.

Проверяемые признаки: обозначены вход и scope; показан обычный и ошибочный/негативный сценарий; ожидаемое отделено от фактического; вывод связан с criterion, источником или явно помеченной интерпретацией.

## Статус исполнения

Документальная демонстрация. Команды и продукты не запускались. Необходимые для будущего trial prerequisites: точный snapshot проекта, выбранный host/runtime, versions, изолированная среда, ограниченные права, владелец приёмки и неизменный oracle. Приведённые форматы учебные, если прямо не приписаны источнику.
